# 지원 범위와 한계 / Support matrix

| 경로 | 환경/의존성 | 범위 | 검증 및 한계 |
|---|---|---|---|
| HWPX ZIP/XML | Python 3.10+, lxml; Windows/Linux/macOS 대상 | 지원하는 본문·표·양식 생성/편집/분석 | 대상 OS는 실제 검증 OS와 다름. 전체 HWPX/OWPML 사양 구현 아님 |
| 표 추출 | 동일; 일부 parser backend 회귀 시험 | 병합·중첩·도형/글상자 구조, 여러 출력 형식 | JSON으로 자식 구조 확인. Markdown/matrix는 구조 손실 가능 |
| HWP 변환 | Windows, 설치·라이선스가 있는 Hancom Office, pyhwpx | HWP → HWPX | 순수 XML 파서가 HWP 바이너리를 읽는 것이 아님 |
| 서명 삽입 | 동일 + Pillow | 특정 마커에 이미지 임베딩 | 인증서 서명 아님. 실제 위치/비율 검수 필요 |
| PDF 내보내기 | Windows/Hancom/pyhwpx + PyMuPDF 검증 | 한글 조판의 PDF 생성 | COM/폰트/한글 버전/보안 모듈에 종속 |
| PDF 캡처·비교 | PyMuPDF + Pillow | 기존 PDF의 페이지 이미지/픽셀 차이 | PDF를 HWPX와 동등하게 검증하지 않음. 자원 한도에 걸리면 중단 |
| GitHub Actions | Ubuntu, Python 3.10/3.12로 작성 | 합성/모킹 회귀 | 원격 실행 결과와 실제 Windows COM은 별도 |

## PDF 자원 한도와 비교 보고서 (현재 pre-release 구현)

현재 PDF 캡처·비교의 DPI는 정수 **72–600**, 최대 **40,000,000 pixels/페이지**, **200,000,000 pixels/작업**입니다. 비교에서는 양쪽의 비교 대상 페이지 렌더링 비용을 모두 합산합니다. 페이지 수가 다르면 공통 페이지까지만 픽셀 비교하므로 `summary.page_count_match`, 양쪽 페이지 수와 `pages_with_diff`를 함께 읽어야 합니다. 크기가 다른 페이지는 RMS를 비교할 수 없어 JSON `rms: null`이며 Infinity를 쓰지 않습니다. 오류 경로에서도 열린 PDF를 닫도록 구현되어 있으나 이것이 전체 네이티브 메모리 안전 보장은 아닙니다.

**`compare_rendered_pdfs.py`의 exit 0은 보고서 생성 성공이지 문서 동일 판정이 아닙니다.** 픽셀 차이가 있어도 0을 반환할 수 있습니다. 보고서와 실제 전체 페이지를 확인하세요. 이 한도는 메모리 bytes의 상한이 아니며 실행시간/디스크/임시파일을 완전히 제한하지 않습니다. 인터페이스는 공개 전 수정될 수 있습니다.

## 보장하지 않는 것

한글 자동화의 `--exclusive-use`는 실행 전 모든 한글 종료와 실행 중 한글 미사용을 전제로 합니다. 시작 시 사용자의 한글을 자동으로 닫지 않으며, 동시 사용의 강제 격리를 보장하지 않습니다. 별도 가상머신은 필수가 아닙니다. 고수준 도구에서 이 옵션을 제공하지 않으면 먼저 변환 CLI로 HWP를 HWPX로 변환하고 XML 경로를 사용하세요.

- 완전한 XSD 검증, 모든 한글 버전/문서 컨트롤/임베딩 객체 지원, 원본 조판의 무조건 보존.
- `page_guard`만으로 실제 페이지 수나 배치가 같다는 결론.
- 화면낭독기 읽기 순서, WCAG/PDF-UA 등 접근성 인증이나 법률적 문서 효력.
- OCR, 임의 위치의 범용 이미지 편집, 암호/DRM 우회, 인증서 기반 전자서명.
- 실제 COM을 CI가 검증했다는 주장, 현재 외부 이용자 수나 운영 SLA.

원본을 보존하고, 결과를 구조·내용·조판별로 확인해야 합니다. 한글이 없는 환경에서는 XML 작업까지만 수행하고 시각 검증은 미완료로 남깁니다. 생성/편집 최종본의 전체 PDF 페이지를 300 DPI 이미지로 열어 확인하기 전에는 문서 품질 검수 완료로 처리하지 않습니다.
